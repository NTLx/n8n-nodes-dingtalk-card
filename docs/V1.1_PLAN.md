# v1.1.0 plan — wide rich notification surface

## Objective

Upgrade the stable v1.0 presentation surface without breaking existing workflows. v1.1 adds a new bounded `universal-v2` A2UI profile that maps directly to the published wide DingTalk template used by ChatGPT automation notifications and reports.

Production template under acceptance: `12a9c7d8-2a47-4750-9959-2069b9df490b.schema`.

The release must preserve `universal-v1`, existing lifecycle operations, request-action callbacks, and raw/Form/Presentation modes. It must not require any n8n service upgrade, restart, database mutation, container change, or configuration change.

## Why this release

The v1.0 `universal-v1` surface intentionally flattens text/keyValue/list blocks into one plain-text variable. Connected use exposed three presentation limitations for desktop DingTalk notifications:

1. cards visually collapse into mostly plain text;
2. report/artifact URLs are displayed as text instead of reliable clickable links;
3. the desktop card does not use the desired wide layout.

A recent Hourly execution also showed a workflow-layer compatibility gap: a typed `keyValue` block carrying `items[]` reached the frozen v1 validator and failed closed. v1.1 keeps the v1 plugin contract strict and fixes that legacy shape in the shared n8n gateway normalizer instead of silently broadening v1.

## Scope

### Plugin: `universal-v2`

Add one new version/profile pair:

- `version: "2"`
- `profile: "universal-v2"`

Descriptor fields:

- `title` — required, non-empty, <= 200 chars
- `summary` — required plain-text summary, non-empty, <= 1000 chars
- `summaryMarkdown` — optional rich summary, <= 1000 chars; defaults to a safely escaped rendering of `summary`
- `tone` — `neutral|info|success|warning|danger`
- `status` — optional, non-empty, <= 50 chars; defaults to upper-case tone
- `generatedAt` — optional, non-empty, <= 100 chars
- `source` — optional, non-empty, <= 200 chars
- `metrics` — exactly 4 `{label,value}` items, matching the fixed four-cell KPI template
- `sections` — optional, at most 8 `{title,markdown,links?}` sections
- `links` — optional, at most 8 root quick links
- `footer` — optional Markdown, <= 500 chars

Link objects are `{label,url}` with an absolute `http` or `https` URL only. Embedded credentials and non-HTTP schemes fail closed. Rich Markdown fields reject HTML tags and ad-hoc Markdown links; navigation must use structured `links[]`. No arbitrary component tree, HTML renderer, JavaScript, CSS, image fetch, or executable action is introduced.

### Fixed template mapping

`universal-v2` maps only to the variables published in the wide template:

- `title`
- `summary_text`
- `meta_markdown`
- `summary_markdown`
- `metric1_label` / `metric1_value`
- `metric2_label` / `metric2_value`
- `metric3_label` / `metric3_value`
- `metric4_label` / `metric4_value`
- `body_markdown`
- `actions_markdown`
- `footer_markdown`
- `config`

`config` is always the stringified JSON value `{"autoLayout":true}` so it can be placed directly in `cardData.cardParamMap` and consumed by the published template.

Sections are rendered deterministically into Markdown. Section and root links are rendered by the plugin from validated URLs, making them clickable without accepting arbitrary component JSON.

### n8n shared gateway

After a v1.1 package is installed through n8n's supported Community Nodes lifecycle:

- switch `ChatGPT → DingTalk Interactive Card` to template `12a9c7d8-2a47-4750-9959-2069b9df490b.schema` for `universal-v2` payloads;
- preserve `universal-v1` compatibility;
- extend the workflow normalizer to expand legacy `{type:"keyValue",items:[{key,value}]}` into standard v1 `{type:"keyValue",label,value}` blocks;
- do not modify n8n service/runtime/database/container/configuration;
- keep delivery verification based on terminal workflow success, node `success=true`, and all `deliverResults[].success=true` until a future synchronous MCP invocation capability exists.

## Release sequence

1. Implement and unit-test `universal-v2` while preserving all v1 tests.
2. Prepare `1.1.0-beta.1` release policy and documentation.
3. Publish beta through the existing GitHub Actions Trusted Publisher/OIDC pipeline.
4. Update the already-installed community node only through n8n's supported Community Nodes lifecycle. If the connected n8n MCP cannot update an installed package, stop at that capability boundary and require the user to click Update in n8n; do not bypass it.
5. Update and validate the shared ChatGPT DingTalk workflow through `n8n-VPS` only.
6. Run real direct-message acceptance with a Mail Daily-style rich payload and verify transport plus rendered-card behavior: wide desktop layout, Markdown hierarchy, clickable links, and 4-cell KPI presentation.
7. Run legacy `universal-v1` regression and the previously failing Hourly `keyValue.items[]` shape through the gateway normalizer.
8. Promote to stable `1.1.0` only after connected-instance acceptance.

## Acceptance gates

### Local / CI

- lint, typecheck, build, tests, package verification pass on supported Node 24 / n8n 2.44.x matrix;
- existing `universal-v1` output is unchanged for current fixtures;
- v2 output values are all strings;
- v2 emits `config={"autoLayout":true}`;
- invalid URLs, HTML tags, unknown fields, malformed metrics/sections/links, and oversized data fail closed;
- raw JSON, Form, Presentation, streaming/finalize, Trigger, and request-action tests remain green.

### Connected n8n / DingTalk

- no n8n service-level mutation occurs;
- package is loaded through supported Community Nodes lifecycle;
- shared gateway uses the new template for v2;
- real DM Create & Deliver returns workflow success, DingTalk node `success=true`, and every `deliverResults[].success=true`;
- desktop DingTalk card is visually wide;
- Markdown hierarchy is rendered rather than flattened plain text;
- HTTP(S) links are clickable;
- KPI region renders four distinct cells;
- legacy v1 remains functional;
- old typed `keyValue.items[]` payload is normalized by the workflow and no longer reaches the strict v1 validator unchanged.

## Non-goals

- no arbitrary DingTalk UI/component JSON;
- no generic HTML/CSS/JS rendering;
- no Form/Selection expansion;
- no new persistent business state or routing in the plugin;
- no n8n service upgrade/restart/config/database changes;
- no claim of exactly-once delivery or Create upsert/deduplication.
